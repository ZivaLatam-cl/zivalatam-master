# Glosario institucional de ZivaLatam

> **Estado:** BORRADOR DE VOCABULARIO — versión 0.1  
> **Finalidad:** mantener un lenguaje consistente y evitar que los mismos términos se utilicen con significados distintos.

Este glosario recoge el uso conceptual declarado o trabajado hasta la fecha. No convierte nombres o capacidades propuestas en productos implementados.

| Término | Uso en la documentación | Estado / cautela |
|---|---|---|
| ZivaLatam | Iniciativa institucional y marco del ecosistema. | En desarrollo conceptual y estratégico. |
| Ecosistema ZivaLatam | Conjunto conceptual de capacidades, productos, módulos e iniciativas relacionados. | No implica que estén implementados u operativos. |
| ZivaID | Plataforma general conceptual de identidad digital para personas y organizaciones. | Propuesta; no es un sistema productivo acreditado. |
| ZivaAccounts | Módulo conceptual de ZivaID para autenticación, sesiones, acceso y permisos. | No es un producto separado ni una implementación confirmada. |
| ZivaDocuments | Área/módulo conceptual de ZivaID para documentos, bóveda, credenciales y presentación controlada. | Propuesta; arquitectura y controles pendientes de validación. |
| ZivaHome | Nombre candidato para una futura interfaz de usuario. | No aprobado ni verificado como marca disponible. |
| ZivaConsole | Nombre candidato para una futura interfaz para desarrolladores. | No aprobado ni verificado como marca disponible. |
| Identidad digital | Representación digital vinculada a una persona u organización, con atributos y evidencias asociados. | No sustituye automáticamente identificaciones o registros legales nacionales. |
| Autenticación | Proceso de comprobar que un usuario controla un autenticador o cuenta. | No demuestra por sí sola que todos los atributos o documentos sean verdaderos. |
| Verificación | Proceso de comprobar una afirmación o evidencia contra una fuente o método definido. | Debe especificar qué se verificó, por quién, cuándo y con qué alcance. |
| Credencial verificable | Afirmación o conjunto de afirmaciones emitidas por una entidad, con mecanismos para comprobar integridad y procedencia conforme a un estándar. | La conformidad depende de implementación y ecosistema; no asumir certificación automática. |
| Bóveda documental | Almacenamiento destinado a conservar documentos fuente del titular con controles de seguridad y acceso. | Diseño conceptual; no prometer invulnerabilidad ni acceso exclusivamente técnico sin validación. |
| Divulgación selectiva | Presentación de atributos específicos, en lugar de revelar necesariamente el documento completo. | Criterio de diseño seleccionado; implementación pendiente. |
| Consentimiento / autorización | Decisión del titular respecto de una solicitud concreta de datos, dentro de límites legales y de política. | No legitima por sí solo cualquier tratamiento o solicitud excesiva. |
| Modelo de reconocimiento | Capacidad transversal conceptual para reconocer habilidades, experiencia, trayectoria y valor productivo mediante evidencias pertinentes. | Metodología y nombre comercial no definidos. |
| Documento fuente | Archivo original conservado en la bóveda documental. | No debe confundirse con una respuesta de atributos al solicitante. |
| Respuesta de identidad | Conjunto limitado de atributos autorizados que se presentan a un tercero para una finalidad concreta. | Concepto de diseño; no equivale a entregar una copia del documento fuente. |
| ADR | Registro de decisión arquitectónica o institucional según el uso definido en el repositorio. | Identificador sujeto a la convención vigente. |
| APR | Registro de aprobación institucional asociado a un alcance y versión concretos. | No equivale a revisión independiente ni a implementación. |

## Reglas de uso

1. Utilizar exactamente los nombres de productos y módulos definidos aquí, salvo que una decisión posterior los cambie.
2. No utilizar “verificado” como sinónimo de “subido”, “almacenado”, “autenticado” o “declarado por el usuario”.
3. Identificar si un término describe una idea, una decisión, un componente implementado o un servicio productivo.
4. Añadir términos nuevos cuando aparezcan en documentos sustantivos y tengan significado estable.
5. Si un término cambia de significado, documentar el cambio y actualizar las referencias afectadas.

## Términos pendientes de definición

- Nombre definitivo de la interfaz universal de usuarios.
- Nombre definitivo de la interfaz para desarrolladores.
- Denominación y metodología del modelo transversal de reconocimiento.
- Vocabulario técnico para niveles de procedencia y verificación de atributos.
- Terminología de identidad organizacional, representación y delegación.
